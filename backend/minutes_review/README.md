# minutes_review — 회의비 증빙(회의록 + 영수증) 검수 핵심 로직

학생 팀이 메일로 보낸 **회의비 지출 증빙(붙임6) + 영수증 첨부철 + 영수증**을 HWP·HWPX·PDF·DOCX 어느 형식으로 받든
같은 중간 표현으로 읽어 C1~C16 항목을 판정하고, 학생에게 보낼 **보완 요청 초안**까지 만든다.
메일 연동(Power Automate)과 웹 화면은 범위 밖이다. LangGraph·FastAPI로 나중에 감쌀 수 있게 프레임워크에 의존하지 않는 순수 파이썬 패키지로 만들었다.

```
파일(들) ─▶ extract.sniff/load ─▶ Document(쪽: 본문 줄 · 표[행[칸(텍스트, 그림)]] · 칸 밖 그림)
                                      │  여러 파일이면 쪽 번호를 이어 한 건으로 합침
                                      ▼
                    fields.extract_fields  ─ 규칙(라벨 칸 → 옆 칸, '라벨: 값' 줄) 우선, 일시·장소 칸만 LLM 보조
                                      ▼
                    checks.run_checks      ─ 계산은 코드, C8 장소·C9 내용·C11 사진만 judge(Claude / 키워드 규칙)
                                      ▼
                    verdict + draft.make_draft ─▶ JSON (항목별 결과·근거·최종 판정·보완 요청 초안)
```

## 실행

```bash
uv venv --python 3.12 .venv && uv pip install -r requirements-dev.txt
uv run python -m minutes_review samples/minutes/M01_정상.hwp --offline           # JSON 결과
uv run python -m minutes_review 회의록.hwp 영수증.pdf --rules club --draft         # 여러 파일 한 건 + 초안만
uv run pytest -q tests/test_minutes_review.py                          # 회의비 검수 테스트
uv run python tools/minutes_samples.py                                           # samples/minutes 재생성
```

```python
from minutes_review import review_files
result = review_files([("회의록.hwp", data)], rules="wemeet")   # dict, json.dumps 가능
```

- `ANTHROPIC_API_KEY`가 있으면 의미 판단을 Claude(`claude-opus-5-5`, `CLAUDE_MODEL`로 변경)가 맡는다. 회의 사진도 이미지로 보내 사진 속 인원과 장소를 판독한다.
- 키가 없으면 키워드 규칙으로 대신한다. 사진 속 인원은 규칙으로 셀 수 없어 C11은 **확인필요**가 되므로, 정상 서류도 오프라인에서는 최종 `확인필요`가 나온다(AI 판독이 있으면 `적합`).

## HWP 처리 방식 비교와 선택

2026-10-28에 실제 양식(`2. SW취업동아리 지출 증빙서류.hwp` 등 3종)으로 확인했다.

| 방식 | 설치 | 표 보존 | 한글 정확도 | 비고 |
|---|---|---|---|---|
| **olefile + BodyText 직접 파싱 (선택)** | `olefile`(BSD, 순수 파이썬)만 | ◎ 칸 단위 행·열 주소, 병합 처리, 칸 안 그림까지 | ◎ UTF-16 원문 그대로 | 실제 양식 3종에서 pyhwp `hwp5html`과 표 내용 동일. 그림 바이트(BinData)도 꺼냄 |
| pyhwp `hwp5txt` | pip 설치 가능하나 `six` 의존성 누락으로 바로 실행 안 됨 | ✕ 표가 `<표>`로만 나오고 칸 내용 없음 | ○ | AGPL-3.0, 2020년 이후 릴리스 없음 |
| pyhwp `hwp5html` | 위와 같음 | ◎ | ◎ | 품질은 좋으나 AGPL이라 서비스에 넣기 부담. XSLT 변환이 느림 |
| LibreOffice + H2Orestart `soffice --convert-to pdf` | 1GB 넘는 설치 + Java, 이 맥에는 없음 | △ PDF로 바꾼 뒤 다시 표 인식 (2단계 손실) | ○ | **직접 시험하지 않음.** 서버 배포·콜드스타트 부담 |
| Upstage Document Parse API | API 키 | ○ HTML 표 | ○ | **직접 시험하지 않음.** 학생 개인정보(이름·서명·카드번호)를 외부로 보내야 하고 유료 |

선택 이유: 필요한 정보는 문단 텍스트, 표 칸, 칸 안 그림뿐이고, 이 레코드 몇 종류는 공개 명세(한컴 'HWP 5.0 문서 파일 구조')대로 읽으면 된다.
그래서 라이선스 부담, 무거운 설치, 외부 전송 없이 표 구조를 가장 정확하게 얻는 직접 파싱을 골랐다.
HWPX(zip + OWPML XML)도 `extract/hwpx.py`로 같이 지원한다. 암호 걸린 HWP와 배포용 HWP는 읽을 수 없다고 오류를 내고, PDF로 다시 내 달라고 안내하게 한다.

형식 판별은 확장자보다 **내용**을 먼저 본다: `%PDF-`, OLE 서명 + `FileHeader`·`BodyText`(HWP), zip 안의 `mimetype`·`Contents/section*.xml`(HWPX), `word/document.xml`(DOCX), PNG·JPEG·GIF(이미지).

## 중간 표현에서 형식 차이를 없앤 방법

- 병합 칸은 한 번만 나온다(PDF의 `None` 자리, DOCX의 `vMerge` 이어진 칸은 버린다). 그래서 "라벨 칸 → 다음 칸" 규칙이 형식과 상관없이 통한다.
- 칸 텍스트는 줄 구조를 남기되 비교·출력에는 공백을 한 칸으로 편 값(`Cell.flat`)을 쓴다. PDF는 칸 너비에 따라 줄이 바뀌기 때문이다.
- PDF는 글자 중심점 기준으로 칸에 배정한다(`crop`을 쓰면 경계 글자가 옆 칸으로 샌다). 그림은 칸 영역 안에 있으면 그 칸의 그림이다.
- HWP·DOCX에는 쪽 배치 정보가 없어서 **쪽 나누기** 위치로 쪽을 나눈다. 샘플은 PDF와 같은 자리에 쪽 나누기가 있어 근거의 쪽 번호까지 같게 나온다.
- 글자 없이 그림만 있는 쪽이나 이미지 파일은 스캔본으로 보고 `needs_ocr`로 표시한다. 영수증이 그림뿐이면 영수증 값이 필요한 항목은 **확인필요**("OCR 필요")가 된다. OCR 구현은 범위 밖이다.

## 판정 항목 (C1~C16)

| ID | 항목 | 판정 | 미충족 시 |
|---|---|---|---|
| C1 | 동아리 구분 체크 (증빙서·첨부철 모두) | 코드 | 보완필요 (두 서류의 체크가 다르면 확인필요) |
| C2 | 동아리 분야 | 참고, 판정 제외 | — |
| C3 | 동아리명 일치 (증빙서 = 첨부철) | 코드 | 보완필요 |
| C4 | 영수증 첨부, 금액 > 0 | 코드 | 보완필요 |
| C5 | 회의일 = 영수증 거래일 | 코드 | 부적합 |
| C6 | 첨부철 기재 날짜·금액 = 영수증 | 코드 | 보완필요 |
| C7 | 결제금액 ÷ 참석 인원 ≤ 한도 | 코드 | 부적합 |
| C8 | 장소: 음식점·카페 불가 | LLM (없으면 키워드) | 부적합 |
| C9 | 회의내용 구체적 + 안내문 삭제 | 안내문·빈 칸은 코드, 구체성은 LLM | 보완필요 |
| C10 | 참석자 전원 서명 (서명 칸에 그림 또는 '(서명)' 외 글자) | 코드 | 보완필요 |
| C11 | 사진 있음(코드) + 사진 속 인원 = 참석 인원·장소(LLM 비전) | 코드+LLM | 보완필요 |
| C12 | 가맹점 주소가 광주 북구 ('북구'만 있으면 확인필요) | 코드 | 부적합 |
| C13 | 결제 시각 20시 이전 | 코드 | 부적합 |
| C14 | 회의 종료 후 1시간 이내 결제 (회의 시작 전 결제는 확인필요) | 코드 | 부적합 |
| C15 | 카드 결제 | 코드 | 부적합 |
| C16 | 영수증에 카드번호 표시 (마스킹 포함) | 코드 | 보완필요 |

최종 판정: 등급이 '부적합'인 항목이 미충족이면 **부적합**, 그 밖의 미충족이 있으면 **보완필요**, 확인필요만 있으면 **확인필요**, 모두 충족이면 **적합**.
항목마다 `evidence`(쪽, 어느 칸, 원문 값), `basis`(기준), `action`(요청 조치), `by`(코드 / Claude / 규칙)를 담는다.

**기준값은 코드에 없다.** 한도, 지역, 결제 마감 시각, 종료 후 허용 시간, 결제수단 단어, 안내문 문구, 항목별 등급은 `rules/wemeet.yaml`(위밋)과 `rules/club.yaml`(SW동아리)에 있다.
담당자 확정 답변을 기다리는 잠정값이어서, 확정되면 YAML만 고치면 된다.

## 보완 요청 초안

`draft = {subject, body, staff_memo, send_needed}`. 본문은 미충족 항목만 "인정 기준에 맞지 않는 항목(부적합)"과 "보완해 주실 항목(보완필요)"으로 나눠 근거·기준·요청을 적는다.
**확인필요 항목은 학생 본문에 넣지 않고** `staff_memo`로 담당자에게만 준다. 담당자가 확인하기 전에 학생에게 잘못된 지적이 가지 않게 하려는 것이다. 담당자가 화면에서 고친 뒤 [전송]하는 흐름을 전제로 했다.

## 안전장치

- 제출 문서 텍스트는 `<item>` 태그 안 데이터로만 보내고, 태그 위조 문자를 바꾸고 길이를 제한한다. 그 안의 지시는 따르지 말고 uncertain으로 두라고 시스템 프롬프트에 적었다.
- 묻지 않은 id나 범위 밖 인원 수가 담긴 LLM 응답은 버린다. LLM이 일시·장소 칸을 보조로 읽은 값은 **원문에 실제 있는 숫자·글자일 때만** 받는다.
- 호출이 실패하면 예외 종류 이름만 남기고 키워드 규칙으로 계속한다.
- HWPX는 외부 엔티티 해석을 끄고 XML 크기를 제한한다. 입력 파일은 20MB, PDF는 60쪽까지 받는다.

`tests/test_minutes_review.py`(35개)는 다음을 확인한다.

- 10건 모두 **4개 형식의 결과 JSON이 완전히 같은지**(항목 결과, 근거 쪽·칸, 필드, 초안까지)
- 케이스별 기대 판정
- LLM 대역으로 정상 건이 4개 형식 모두 `적합`이 되는지, 사진 인원이 다르면 C11 미충족이 되는지
- 설정 파일 값을 바꾸면 판정이 바뀌는지
- 이미지 영수증이 OCR 필요로 처리되는지
- 형식을 확장자가 아니라 내용으로 판별하는지
- LLM 보조 값 검증과 프롬프트 인젝션 방어
- 실제 빈 HWP 양식 읽기 (로컬에 파일이 있을 때만)

샘플 HWP는 `tools/hwpkit.py`가 OLE 복합 문서와 레코드를 직접 쓴다. 글자·문단 모양 같은 서식 레코드는 넣지 않아서 한글에서 열면 서식이 깨질 수 있다.
그래도 구조는 명세대로라서 pyhwp `hwp5proc models`로도 표 칸 38개, 그림 5개, 문단 58개가 그대로 해석되는 것을 따로 확인했다.
실제 한글 파일 읽기는 실제 빈 양식으로 검증했다(위 표).

## 알려진 한계 / 확정 필요

- **양식 차이**: 회의비 증빙 양식(붙임6)의 '동아리 구분'에는 **SW취업 칸이 없고** 영수증 첨부철에는 있다. 취업동아리는 증빙서에 체크할 칸이 없을 수 있어, 현재 C1은 두 서류 모두 체크를 요구하되 체크가 서로 다르면 확인필요로 둔다. 담당자 확인이 필요하다.
- 사진·종이 영수증 OCR은 범위 밖이다(확인필요로 넘김). 실제 제출의 상당수가 사진 영수증이면 OCR이 다음 과제다.
- 1일 1회·월 한도, 참석자 자격(회원 명단)은 서류 한 건으로는 판정할 수 없어 넣지 않았다(1차 MVP와 같음).
- 현금 결제 건(C15 미충족)에도 C16 요청 문구가 "카드 매출전표 제출"로 나온다. 담당자가 초안에서 지우면 된다.
