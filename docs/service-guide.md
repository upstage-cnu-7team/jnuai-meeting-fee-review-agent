## 1. 무엇을 하는 서비스인가

전남대 **인공지능혁신융합대학사업단**은 학생 팀(동아리·위밋·캡스톤·AIM·해커톤)에 회의비를 지원한다. 학생은 회의를 한 뒤 **회의록 파일**(사업단 양식, 영수증 사진을 안에 붙임)을 담당자 학교 메일로 보낸다. 담당자는 한 건씩 열어 17가지 기준을 눈으로 확인하고, 문제가 있으면 학생에게 보완 메일을 쓴다.

이 서비스는 그 검토를 자동화한다.

1. 학생이 담당자 학교 메일로 증빙을 보낸다. (학생 쪽 변화 없음)
2. 서비스가 메일과 첨부를 자동으로 가져온다.
3. Upstage AI로 회의록·영수증 값을 읽고, **코드와 LLM이 기준 17개를 하나씩 판정**한다.
4. 담당자 화면에 팀별로 정리하고, 항목별 근거와 **회신 초안**을 보여 준다.
5. 담당자가 확인·수정한 뒤 학생에게 회신한다.

**핵심 원칙: AI가 결정하지 않는다. AI는 근거를 정리하고 초안을 만들 뿐, 최종 확인과 회신은 담당자가 한다.**

### 사용자

| 사용자 | 계정 | 맡은 프로그램 |
|---|---|---|
| 동아리 담당자 | `club-manager` | 동아리 · AIM · 해커톤 |
| 위밋 담당자 | `wemeet-manager` | 위밋 · 캡스톤 |
| 관리자(우리 팀) | `admin` | 5개 전부 + 기준 관리 |

- 담당자는 **자기 메일함으로 온 제출만** 본다. 다른 담당자 프로그램은 `403`이다.
- 팀은 99개다(동아리 41, 위밋 41, 캡스톤 9, AIM 3, 해커톤 5). 위밋과 동아리 팀 목록은 같다.
- 같은 이름 팀(예: 테라바이트는 동아리·AIM·해커톤에 다 있다)은 **프로그램마다 다른 팀**이다.

## 3. 메일을 어떻게 받나 (확정, 두 담당자 모두 동작 확인)

담당자 메일은 학교가 직접 운영하는 Exchange 서버의 웹메일(**OWA** = Outlook Web Access, `email.jnu.ac.kr/owa`)이다. 여기서는 할 수 있는 게 거의 없어서 여러 번 길을 바꿨다.

| # | 시도 | 결과 |
|---|---|---|
| 1 | Graph API로 메일 읽기 | 앱 등록 권한 없음(401) |
| 2 | Outlook 규칙 외부 전달 | 학교 정책으로 차단(5.7.520) |
| 3 | OneDrive 동기화 | 동작하지만 PC가 늘 켜져 있어야 함 |
| 4 | 개인 outlook.kr 경유 | 계정 잠김, IMAP 기본 인증 꺼짐 |
| 5 | 자체 도메인 `jnuai-meetingfee.com` | Cloudflare 수신·Resend 발신 확인 → **채택** |
| 6 | 단어 필터(회의비·회의·지출) | 사업단이 **증빙이 아닌 다른 서류가 밖으로 나가는 것**을 보안상 꺼림 → **팀명 필터**로 변경 |
| 7 | 담당자 OWA에서 외부 리디렉션 | 조용히 차단됨 |
| 8 | 종희 학교 메일 + Power Automate 중계 | **현재 경로** |

**현재 경로**

1. 담당자 OWA 받은 편지함 규칙: 제목·본문에 팀 키워드가 있으면 중계 학교 계정로 리디렉션한다. 담당자 계정에는 **이 규칙 1개만** 추가했고 다른 설정은 건드리지 않았다.
2. 종희 계정은 Microsoft 365 클라우드라 Power Automate가 된다. 흐름 "회의비 증빙 수집 필터 (서비스)"가 제목·본문·**첨부 파일명**을 정규화(소문자, 공백·기호 제거)해 팀 키 123개와 비교한다.
3. 하나라도 맞으면 `submit@jnuai-meetingfee.com`으로 `[수집] 원래 제목` + 메타데이터 + 첨부를 보낸다.
4. Cloudflare Email Routing이 받는다. 지금은 Gmail로 전달하고, 다음 단계에서 **Email Worker가 메일 원본(raw MIME)을 FastAPI 웹훅으로** 넘긴다.

**왜 이렇게 돌아가나**

- 담당자 OWA에서는 Power Automate를 못 쓴다.
- OWA 규칙으로 외부 주소에 보내면 학교 서버가 조용히 막는다. 학교 내부 주소(종희 메일)로는 간다.
- Power Automate에서 서버로 바로 보내는 "HTTP" 동작은 프리미엄이라 학생 라이선스(Free + Office 365)로는 쓸 수 없다(10/30 확인). 그래서 무료 "메일 보내기"로 내보내고, 그 메일을 Cloudflare가 무료로 받아 웹훅으로 바꿔 준다. 서버가 직접 메일을 받으려면 25번 포트가 필요한데 클라우드 서버는 보통 막혀 있다.
- 첨부 없는 메일도 들어온다(10/30에 조건 제거). 서비스가 "미첨부" 보완 요청 대상으로 처리한다.

**지켜야 할 것:** 담당자 메일 내용을 읽지 않는다. 비밀번호는 담당자·종희가 직접 입력한다. 담당자 계정 설정 절차는 `mail/manager-visit-runbook.md` (내부 기록, 공개본에서 제외) 그대로만 한다.

**남은 위험:** 종희 개인 학교 메일함을 거친다. 전용 계정으로 바꾸거나 담당자 동의를 받아야 한다.

## 4. 메일 거르기, 프로그램과 팀 정하기

### 받는 메일 (2026-10-31 결정)

- **2026-10-30(금) 00:30 이후 받은 메일부터** 접수한다. 그 전 메일은 시험 메일이 섞여 있어 받지 않는다(`.env`의 `INTAKE_SINCE`).
- **회의비 증빙 양식이 아닌 첨부만 있는 메일은 저장하지 않고 버린다.** 사업단이 증빙이 아닌 서류가 밖에 보관되는 것을 꺼리기 때문이다. 양식 판단은 문서 안에 '회의비 (지출) 증빙' 제목이 있거나, 팀명·회의명·참석자·서명 칸이 모두 있는지로 한다.
- 첨부가 없는 메일은 받는다. '미첨부' 보완 요청 대상이다.
- 웹훅(Email Worker)이 붙기 전 Gmail에 쌓인 메일은 `.eml`로 내려받아 `tools/import_eml.py`로 한꺼번에 넣는다. 같은 규칙(시작 시각, 양식 거르기, 중복 방지)을 쓴다.
- 사진·스캔본은 글자를 읽기 전에는 양식인지 알 수 없어 일단 받는다.

### 양식 확인 (F00, 2026-10-31)

제출 파일이 **사업단 회의비 지출 증빙 양식(별첨 1-1)**인지 먼저 본다. 기준은 손으로 적은 단어가 아니라 **빈 양식 파일 `backend/forms/aicollege/별첨1-1_회의비_지출증빙_양식.hwp`를 문서 리더로 읽어 뽑은 칸 구조**다.

- 칸 13개: 팀명, 회의명, 회의일시, 회의장소, 회의내용, 참석자 명단, 소속, 학번, 이름, 서명, 영수증, 사용 비용, 결제자
- 제출본에서 칸 이름이 90% 이상 보이면 **양식 일치**, 60~90%면 **일부 다름**(없는 칸을 알려 줌), 60% 미만이면 **양식 아님**(접수하지 않고 버림)
- 빈 양식의 예시 글('회의 주제', '활동내용 자세하게 작성', '작성자명', '2026.00.00.(월)' 등)이 그대로 남아 있으면 **채우지 않은 칸**으로 알려 준다. 서명·영수증 칸의 안내 글은 지우지 않고 붙이는 경우가 많아 근거로 쓰지 않는다.
- 결과는 조건 목록 맨 앞 **F00**으로 나온다. 일치하면 충족, 다르거나 채우지 않은 칸이 있으면 **확인필요**(담당자 메모로만, 학생 회신에 자동으로 넣지 않음). 지침에서 뽑은 조건(R01~R17)과는 별개의 사전 확인이다.
- 스캔본은 Upstage OCR 글자로 대조한다.

### 프로그램

회의비 증빙 양식은 모든 프로그램이 같고, **문서 맨 위 별첨 제목의 단어만 다르다.**

| 별첨 제목 단어 | 프로그램 | 담당자 |
|---|---|---|
| 캡스톤 | 캡스톤 | 위밋 담당자 |
| WE-Meet | 위밋 | 위밋 담당자 |
| 동아리 | 동아리 | 동아리 담당자 |
| (없음, 그냥 '회의비 증빙') | **AIM 챌린지 또는 해커톤** | 동아리 담당자 |

AIM 챌린지와 해커톤은 제목으로 구분할 수 없다. 그래서 다음 순서로 정한다.

1. 회의록 팀명을 **AIM 팀 목록(3팀)과 해커톤 팀 목록(5팀)**에서 찾는다. 한쪽에만 있으면 그 프로그램이다.
2. 두 곳에 다 있는 팀은 지금 **테라바이트 하나뿐**이다. 회의록 참석자 이름을 **팀원 명단**(`rules/teams.yaml`의 `members`)과 대조해 겹치는 쪽으로 정한다. 명단은 종희가 받아서 채운다.
3. 명단이 없거나 대조가 안 되면 **프로그램 미확정**으로 둔다. 담당자 화면의 "프로그램 미확정" 목록에 뜨고, 상세의 담당자 메모 맨 위에 이유가 나온다(예: "'테라바이트' 팀은 AIM 챌린지·해커톤에 모두 있습니다. 팀원 명단이 아직 등록되지 않았습니다. 프로그램과 팀을 지정해 주세요."). 담당자가 프로그램과 팀을 고른다.

스캔본은 글자 층이 없어 Upstage OCR 글자로 별첨 제목을 본다. 글자를 전혀 못 읽으면 담당자 메일함과 메일 제목·본문의 프로그램 단어로 좁힌다.

### 팀

회의록 팀명을 가장 믿고, 그다음 메일 제목·본문·첨부 파일명을 팀 키와 대조한다. 키는 `tools/team_keys.py`가 팀명에서 자동으로 만든다(소문자, 공백·기호 제거, 괄호 안 이름 따로, 긴 이름은 조각). 흔한 단어 같은 짧은 이름(`strict: true`)은 메일 글자만 맞아서는 확정하지 않는다. 못 정하면 "팀 미확정"이고 담당자가 지정한다.

## 5. 검수 기준은 어디서 왔나

1. **입력:** 사업단 문서 2개. `별첨1_회의비_참고사항.hwp`(지침)와 `별첨1-1_회의비_지출증빙_양식.hwp`(회의록 양식).
2. **Upstage Information Extract**로 지침 값 23개를 뽑는다: 결제 수단, 결제 마감 시각, 1인당 한도, 식비·다과비 결제 시점, 최소 회의 시간, 허용·불가 지역, 영수증 규정, 서명 규정, 제출 기한, 양식 안내 등. 결과 예: 결제 마감 20:00, 1인 20,000원, 광주 북구.
3. **코드가 조건 초안 20개**를 만든다(`build_rules.py`). 조건마다 판정 주체(코드/Solar), 미충족 시 등급(부적합/보완필요), 기준값, **지침 원문 근거**를 붙인다.
4. **담당자가 확정한다.** 실제 운영 기준을 듣고 고쳤다.
   - 수정: 제출 기한 "사용 후 1주일" → **"사용일로부터 7일째 되는 날 18:00 전"**
   - 추가: **영수증 사진을 못 읽으면 학생에게 다시 제출 요청** (2026-10-31 변경, 처음엔 확인필요)
   - 제외: R18 1회/1일, R19 수업시간 회의, R20 카드 1일 전 예약·반납 (서류로 판정할 수 없음)
5. 확정본은 DB `rule_sets`에 **버전으로** 저장한다(첫 실행 때 yaml에서 넣음). 판정 결과마다 **사용한 기준 버전과 모델**을 남긴다.

AI가 만든 조건이 담당자 확인 없이 판정에 쓰이지 않게 하려는 절차다. 지침이 바뀌면 1~4만 다시 하면 된다.

> 위밋 지침·기준은 아직 받지 못했다. 지금은 동아리 기준(R01~R17)만 확정이다.

## 6. 검수 조건 상세 (동아리 기준 v1, R01~R17)

### 판정 결과 값

| 값 | 화면 | 뜻 |
|---|---|---|
| `met` | ✓ 충족 | 기준에 맞음 |
| `unmet` | ✗ 미충족 | 기준에 안 맞음. 등급(`severity`)에 따라 부적합 또는 보완필요 |
| `review` | ? 확인필요 | 서비스가 확신하지 못함. **담당자가 봐야 함** |
| `excluded` | — 제외 | 이번 기준에서 뺀 조건(R18~R20) |

### 등급

- **부적합(`reject`)**: 회의비로 인정할 수 없음. 고쳐서 될 일이 아님(주말 사용, 20시 이후 결제, 주류 등).
- **보완필요(`needs_fix`)**: 서류를 고치면 됨(서명 누락, 승인번호 없음 등).

## 7. 판정이 틀리지 않게 하는 원칙

### 계산은 코드, 의미 판단만 LLM

- **코드:** 날짜, 요일, 시각, 금액, 1인당 한도, 지역, 회의 시간, 승인번호, 금액 일치, 제출 기한
- **Solar:** 술집·주류, 회의 장소, 회의내용 구체성, 식비/다과비 구분
- **글자로 분명한 위반은 코드가 먼저 잡는다.** 장소에 '카페', 품목에 '맥주'처럼 단어로 확실한 경우는 Solar 답과 관계없이 미충족이다. 2026-10-31 재실행에서 Solar가 이유에는 '위반'이라 쓰고 결정은 ok를 준 사례(A11)가 있었다. Solar 답은 이유를 먼저 쓰고 결정을 나중에 쓰게 하고 `temperature=0`으로 받는다.
- LLM에 숫자 비교를 맡기지 않는다. Solar에는 장소·가맹점·품목·회의명·내용만 넘기고, `<data>` 안의 지시는 따르지 말라고 못 박는다(프롬프트 주입 방지). 답은 JSON 스키마로만 받는다.

### 추출값을 그대로 믿지 않는다

실험에서 Information Extract의 예/아니오 값은 자주 틀렸다.

- **서명(`has_signature`)**: HWP는 모든 케이스에서 4명 전원 '없음', 결제자 서명은 48건 전부 '없음'으로 나왔다. → 파이썬 문서 리더(olefile·python-docx·pdfplumber)로 **서명 칸 안에 그림이 있는지** 직접 본다. 그림 없이 글자만 있으면 워드 작성 서명이다.
- **영수증 첨부(`receipt_attached`)**: 값을 다 뽑고도 `false`를 준 사례가 있었다(A16 PDF). → **영수증 칸 그림 + 영수증 값이 실제로 뽑혔는지**로 본다.
- **스캔본(글자 층 없는 PDF)**: 칸 정보가 없다. Upstage **Document OCR**의 글자 좌표로 '서명' 머리글과 이름 행을 찾아 서명 칸을 자르고, 표 테두리를 지운 뒤 **잉크 비율 0.6% 이상**이면 서명 있음으로 본다. 칸 안에서 OCR이 한글 2자 이상을 읽으면 워드 작성이다.
- 숫자·날짜·시각·주소·승인번호·품목은 실험 48건 모두 판정에 맞게 나왔다.

### 영수증 사진을 못 읽으면 다시 제출 요청

영수증은 별도 파일이 아니라 **회의록 파일 안에 사진으로 붙어 온다.** 문서 전체 추출에서 영수증 값이 비면 **영수증 사진만 잘라 한 번 더** Upstage에 보낸다. 영수증 사진이 흐리거나 잘려 글자를 못 읽으면 추측하지 않고 **R01 미충족(보완필요)**으로 학생에게 "선명한 영수증 사진으로 다시 제출"을 요청한다. 사람도 읽기 어려운 영수증은 검수할 수 없기 때문이다(2026-10-31 결정, 이전에는 확인필요). 이때 영수증 값에 기대는 다른 조건(승인번호·금액·날짜 등)은 미충족을 덧붙이지 않고 "판정 보류"로 담당자 메모에만 둔다. **영수증 자체가 첨부되지 않았으면**(칸도 비고 값도 없음) 영수증 조건들은 아예 띄우지 않고 R01 "영수증 미첨부" 하나만 보여 준다(2026-11-02).

네이버 메일은 10MB가 넘는 파일을 첨부가 아니라 **본문의 대용량 링크**로 보낸다. 검수를 시작할 때 본문의 `bigfile.mail.naver.com` 링크에서 파일을 받아 첨부로 더한다. 링크가 만료되었거나 받지 못하면 학생 미제출이 아니라 담당자 메모로 남긴다. 10MB가 넘는 파일은 Upstage와 미리보기에 사진만 줄인 사본을 쓰고, 판정(서명·영수증 칸)은 원본으로 한다.

### 애매한 구분은 두 방식으로 계산

식비/다과비처럼 구분이 애매하면(예: 아메리카노·쿠키·샌드위치를 Solar는 식비, 품목 단어로는 다과비로 봄) 두 방식으로 모두 계산한다. 둘 다 위반이면 미충족, 둘 다 통과면 충족, 엇갈릴 때만 확인필요다. 담당자 화면의 조건 줄을 펼치면 "식비로 보면: 위반 / 다과비로 보면: 통과"가 나란히 보인다.

### 애매하면 확인필요, 학생에게는 미충족만

허위 지적을 피하는 게 우선이다. 학생 회신 초안에는 **미충족만** 넣고, 확인필요는 **담당자 메모(`internal_notes`)**로만 보여 준다.

### 비용과 속도

- 같은 파일은 **파일 해시로 캐시**해 Upstage에 다시 보내지 않는다. 재판정은 캐시로 한다.
- Information Extract는 **초당 1건**이라 전역으로 간격을 맞춘다. 실패하면 3회 재시도하고, 그래도 안 되면 `processing_status=failed`로 두고 원본은 보여 준다.
- 1건 검수에 20~60초 걸린다. 메일 수신과 검수를 분리해 대기열로 돌린다.

### 개인정보

학생 이름, 학번, 서명, 카드번호가 담긴다.

- 로그에 원문을 찍지 않는다. 오류 메시지에도 넣지 않는다.
- API 응답에서 학번(`2023****`)과 카드번호를 마스킹한다.
- 원본 이미지는 담당자 검토용이라 가리지 않는다. 화면 캡처·공유 기능은 넣지 않는다.
- 쪽 이미지·다운로드 주소는 30분 뒤 만료되는 서명 URL이다.

### 시험 결과 (가상 데이터)

| 시험 | 결과 |
|---|---|
| 정상·위반 18케이스 × 4형식(hwp·pdf·docx·scan), 기대 조건만 정확히 걸림 | **72/72** |
| 17개 항목 결과 4형식 일치 | 18/18 |

**시험 파일:** 가상 회의록 18케이스. HWP는 **사업단 원본 빈 양식(별첨 1-1)에 값을 채운 것**이고, PDF·DOCX는 같은 표를 코드로 다시 그린 것, 스캔은 그 PDF를 이미지로 바꾼 것이다(`tools/aicollege_samples.py`). 지침에서 뽑은 기준은 `guide.ie.json`에 있다(Upstage 추출이 서명 안내를 '자필서명/전자서명 불가'로 잘못 합친 것이 보여, R14 이름은 양식 원문대로 '자필·전자, 워드 작성 불가'로 확정했다).

**아직 안 한 것:** 실제 제출본(휴대폰으로 찍은 영수증 사진이 붙은 회의록, 원근 왜곡·그림자·손글씨) 시험. 지수가 맡는다. 잉크 기준 0.6%는 가상 18건으로 정한 값이다.

|---|---|---|
| S0 로그인 | 아이디·비밀번호(우리가 발급). 학교 계정 로그인은 안 함 | P0 |
| S1 목록 | 상단 프로그램 탭(`user.programs` 순서), 요약 카드(오늘 접수·미확인·AI 확인필요·보완필요·부적합·전송 실패), 팀 사이드바(미확인 많은 순, "팀 미확정"), 제출 목록(서버 정렬: 처리 실패 → 미확인[부적합→보완필요→확인필요→적합→검수 중] → 확인완료) | P0 |
| S2 상세 | 왼쪽 원본(쪽 이미지, 확대, 다운로드), 오른쪽 추출 요약·조건별 결과(미충족→확인필요→충족)·회신 초안 | P0 |
| 항목 수정 | 각 조건을 [충족으로]/[미충족으로] + 메모. 바꾸면 종합 판정과 초안이 다시 계산된다. 원래 AI 결과도 함께 보인다 | P1 |
| S3 팀 상세 | 별칭, 알려진 학생 주소, 제출 이력 | P1 |
| S4 기준 보기 | 확정 기준 버전과 조건 17개(읽기 전용) | P2 |

한 제출 건에는 상태가 4가지 있다. 섞지 않고 배지를 따로 보여 준다.

| 상태 | 값 |
|---|---|
| 처리 `processing_status` | 대기 중 → 검수 중 → 완료 / 처리 실패 |
| AI 판정 `verdict` | 적합 / 보완필요 / 부적합 / 확인필요 |
| 담당자 확인 `review_status` | 미확인 / 확인완료 |
| 회신 `reply_status` | 없음 / 초안 / 전송 중 / 전송 완료 / 실패 / 회신 안 함 |

**쪽 이미지:** 담당자가 원본을 서비스 화면에서 바로 보도록 모든 첨부를 150dpi PNG로 바꿔 준다. PDF·스캔본은 원본을 그대로 그린다. HWP·HWPX는 LibreOffice가 읽지 못해서(2026-10-31 시험: HWP 5.0·HWPX 모두 실패, DOCX도 한글 글꼴이 빠짐), 파이썬 문서 리더가 읽은 표·칸·그림을 나눔고딕으로 다시 그린 **미리보기**를 만든다. DOCX도 같은 방식이다. 원래 모양과 똑같지는 않으므로 [원본 다운로드]를 함께 둔다.

## 9. 회신 (잠정, 담당자와 논의 필요)

담당자 메일이 학교 자체 Exchange라 **서비스가 담당자 이름으로 자동 발송할 수 없다.** 우선 이렇게 간다.

| 버튼 | 동작 |
|---|---|
| [웹메일에서 열기] | OWA 새 메일 창 주소(`reply.compose_url`)에 받는 사람·제목·본문을 채워 새 탭으로 연다 |
| [초안 복사] | 주소 길이 제한(한글 본문 약 200자) 때문에 본문이 길면(`compose_truncated=true`) 복사해 붙인다 |
| [보냈음 표시] | 담당자가 보낸 뒤 누른다 → `reply_status=sent`, `review_status=confirmed` |
| [확인완료만] | 적합이라 회신이 필요 없을 때 → `reply_status=not_needed` |

제약: 스레드 회신이 아니라 새 메일이다. 서비스는 실제로 보냈는지 알 수 없다. 학교 웹메일이 이 주소 방식을 지원하는지는 **다음 담당자 방문 때 시험**한다. 서비스 직접 발송(`noreply@jnuai-meetingfee.com` + 담당자 참조, `POST /reply/send`)은 **보류**다. Resend 도메인 인증과 학교 메일 도착은 확인했다.

회신 초안 모양:

```
안녕하세요, 인공지능혁신융합대학사업단입니다.
○○ 팀에서 제출해 주신 회의비 증빙을 확인했습니다.

■ 회의비 인정 기준에 맞지 않는 항목      ← 부적합 등급 미충족
1. 20:00 이전 결제: 20:25에 결제했습니다. 20:00 이전 결제만 인정됩니다.

■ 보완해 주실 항목                       ← 보완필요 등급 미충족
2. 참석자 전원 서명: 박다솜 님의 서명이 없습니다.

위 내용을 반영해 다시 제출해 주세요.

인공지능혁신융합대학사업단 드림
```

## 10. 기술 구조

| 항목 | 선택 | 이유 |
|---|---|---|
| 서버 | **FastAPI** | 프론트 API, 메일 웹훅, `/docs`로 프론트가 스키마를 본다 |
| AI | Upstage **Information Extract**(23필드), **Solar `solar-pro4`**(의미 판단), **Document OCR**(스캔 서명 좌표) | 실험 72/72 |
| 흐름 | **LangGraph**(가볍게) | 형식 분기(디지털/스캔), 단계 재시도. 판정 로직은 일반 함수, 그래프는 순서만 |
| DB | **SQLite + SQLAlchemy** | 담당자 2명·팀 ~100개 규모. `DATABASE_URL`만 바꾸면 Postgres |
| 문서 읽기 | `minutes_review/extract`(olefile·python-docx·pdfplumber·pypdfium2) | HWP·HWPX·DOCX·PDF의 표·칸·그림 |
| 인증 | 아이디·비밀번호(argon2) + JWT, 이미지는 서명 URL | |
| 패키지 | **uv** (`pyproject.toml` + `uv.lock`, Python 3.12) | 팀원·서버·Docker 환경이 같아진다 |
| 배포 | Docker, Azure for Students 후보 | 12월 초중순까지 운영 |
| 메일 | Cloudflare Email Routing(수신), Resend(발신) | 자체 도메인 |
| RAG/ChromaDB | **핵심 경로에서 안 씀** | 추출 필드가 고정이고 기준이 확정 조건이라 검색이 필요 없다. 넣는다면 "지침 원문 근거 인용" 보조 기능으로만 |

### 백엔드 폴더

```
backend/app/
  main.py  config.py  db.py  models.py  security.py  errors.py  seed.py
  api/        라우터 (frontend-api.md와 1:1)
  review/     판정 로직 (프레임워크 독립 함수)
    upstage.py      IE·OCR·Solar 호출 + 해시 캐시 + 초당 1건
    readers.py      형식 판별, 칸 안 그림(서명·영수증)
    signature.py    스캔본 서명 칸 잉크 판정
    conditions.py   R01~R17 판정
    verdict.py      종합 판정
    draft.py        회신 초안 (미충족만, 확인필요는 메모)
  graph/      LangGraph 검수 흐름
```

### DB 테이블

`users`(계정·맡은 프로그램·메일함), `teams`(프로그램별 팀·별칭), `rule_sets`(기준 버전), `submissions`(제출 건과 상태 4개), `files`(첨부, 해시, 쪽 정보), `checks`(조건별 결과·담당자 수정), `replies`(회신 초안·상태), `upstage_cache`(응답 캐시).
