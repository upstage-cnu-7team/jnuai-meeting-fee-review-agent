# 인공지능혁신융합대학사업단 회의비 증빙 — Upstage 3형식 시험 (2026-10-28)

정식 설계 전 시험용 스크립트. 같은 가상 회의록을 HWP·PDF·DOCX로 만들어 Upstage 파싱·추출·판정이 되는지 확인했다.

```bash
uv run python tools/aicollege_samples.py <빈 양식 별첨1-1.hwp> out/      # A01_정상.hwp/.pdf/.docx
set -a; . ./.env; set +a                                                 # UPSTAGE_API_KEY

uv run python experiments/aicollege_upstage/judge.py out/A01_정상.{hwp,pdf,docx}.ie.json
```

## 알게 된 것

- HWP는 서식(DocInfo)이 완전한 파일만 Upstage가 받는다. 직접 만든 최소 HWP는 손상 파일로 거부된다 → 실제 양식에 값을 채우는 방식(`tools/aicollege_samples.py`).
- 한글은 빈 문단에 PARA_TEXT 레코드를 두지 않는다. 줄바꿈만 든 레코드를 남기면 손상 파일 취급.
- 그림 개체의 자르기·사각형 좌표는 원본 크기(픽셀×75 HWPUNIT) 단위, 표시 크기는 축소 행렬로 맞춘다. 안 그러면 그림이 잘린다.
- 작고 흐린 서명은 Information Extract가 '서명 없음'으로 볼 수 있다 → '서명 없음'은 바로 미충족으로 두지 말고 확인필요.
- R17(1회/1일, 수업시간 회의 불가, 사용 후 1주일 내 제출)은 서류 한 건으로 판정할 수 없다 (이력·시간표·메일 접수일 필요).

첫 실행은 47/48이었다. A16 PDF에서 추출이 영수증 값을 다 뽑고도 `receipt_attached=false`를 줘서 R01이 잘못 걸렸다. → 첨부 여부를 추출의 예/아니오가 아니라 **영수증 칸 안 그림 + 영수증 값이 실제로 뽑혔는지**로 판정하도록 고쳤다.

### 추출을 그대로 믿으면 틀리는 곳

- **서명**: 추출의 `has_signature`는 거의 믿을 수 없다. HWP는 모든 케이스에서 4명 전원 '없음', 결제자 서명은 48건 전부 '없음', PDF·DOCX도 매번 1~2명 놓침. 칸 안 그림 확인(로컬 리더)으로 판정해서 R14·R16이 맞았다.
  → 스캔 PDF처럼 칸별 그림 정보가 없는 제출은 다른 방법(Document Parse의 그림 위치, 비전 LLM)이 필요하다. 미해결.
- **첨부 여부 같은 예/아니오 항목**은 다른 추출값과 모순될 수 있다 → 값의 존재로 교차 확인.
- 숫자·날짜·시각·주소·승인번호·품목은 48건 모두 판정에 맞게 나왔다.
- Solar 식비/다과비 구분(A08 다과비), 술집·주류(A05 호프·생맥주), 장소(A11 카페), 내용 부실(A16)도 세 형식 모두 맞았다.

## 3차 시험: 스캔 PDF 서명 판정 (2026-10-28)

`tools/scanify.py`로 PDF를 글자 층 없는 이미지 PDF(150dpi 회색조, ±0.8° 기울임, 점 노이즈, JPEG 70)로 바꿔 네 번째 형식 `scan`을 추가했다. 케이스도 2건 추가했다: A17 결제자 서명 누락, A18 워드로 친 서명(서명 칸에 이름을 타자로 입력 — 양식상 '워드작성 서명 불가').

스캔본은 칸 정보가 없으므로 `scan_signature.py`가 **Upstage OCR(model=ocr)의 글자 좌표**로 서명 칸을 찾는다.
- '서명' 머리글과 같은 줄에 '이름'·'학번'이 있으면 참석자 표, '학번' 없이 '이름'만 있으면 결제자 표다.
- 서명 열(머리글 x)과 이름 행(이름 단어 y)이 만나는 칸을 잘라 판정한다.
- 칸 안에서 OCR이 한글 2자 이상을 읽으면 → **워드 작성 서명**.
- 아니면 표 테두리를 지운 뒤 잉크(진한 픽셀) 비율이 0.6% 이상이면 → **서명 있음**.

| 결과 | |
|---|---|
| 기대 조건만 정확히 걸림 | **72/72** (18케이스 × hwp·pdf·docx·scan, `results_run4_scan.txt`) |
| 17개 항목 결과까지 4형식 일치 | 18/18 |
| 스캔본 서명 칸 판정 (참석자 72 + 결제자 18) | 90/90 — 서명 칸 잉크 최소 2.1%, 빈 칸 최대 0.03% |

디지털 파일(hwp·pdf·docx)도 서명 칸에 그림 없이 글자만 있으면 워드 작성 서명으로 본다(`_sig`).

### 시험 중 고친 것

- 첫 실행은 71/72였다. A17 스캔의 빈 결제자 서명 칸이 '서명 있음'(잉크 2.1%)으로 나왔다. 원인은 스캔 기울기로 **표 테두리가 비스듬해져** '한 줄 전체가 진한 행·열' 방식으로는 지워지지 않은 것이다.
- 덩어리 방식도 실패했다. 가로·세로 테두리가 모서리에서 붙어 한 덩어리가 되기 때문이다.
- 최종 방식: 방향별로 1픽셀 흔들림을 허용한 긴 줄(가로 40px 이상, 세로 칸 높이 80% 이상)을 테두리로 지운다.

### 남은 위험

- 시험 스캔은 컴퓨터로 만든 깨끗한 스캔이다. 실제 휴대폰 촬영(원근 왜곡, 그림자, 손글씨 이름)은 아직 시험하지 않았다.
- 손글씨 서명이 또박또박해서 OCR이 이름으로 읽으면 '워드 작성'으로 오판할 수 있다 → 실제 운영에서는 '워드 작성' 판정을 확인필요로 낮추는 것을 검토한다.
- 잉크 기준 0.6%는 이 시험 18건으로 정한 값이다.
