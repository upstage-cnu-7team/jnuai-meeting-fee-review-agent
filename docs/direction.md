# 최종 방향 (2026-10-30 기준)

7조 회의비 증빙 자동 검수 Agent에서 **지금 확정된 것**, **잠정인 것**, **바뀐 이유**를 한 곳에 모은 문서다. 세부 내용은 각 문서 링크를 따라간다.

## 1. 무엇을 만드나

- 대상: 인공지능혁신융합대학사업단 담당자 2명(동아리 담당자, 위밋 담당자)
- 흐름: 학생이 담당자 학교 메일로 회의비 증빙(회의록 + 영수증)을 보낸다 → 서비스가 메일을 모은다 → Upstage로 검수한다 → 담당자 화면에 결과와 회신 초안을 보여 준다.
- 최종 발표: **11/7**

## 3. 메일 수집 경로 (확정, 두 담당자 모두 동작 확인)

```
학생 → 담당자 학교 메일 (OWA)
  └ OWA 받은 편지함 규칙: 제목·본문에 팀 키워드 → 중계 학교 계정로 리디렉션
      └ 종희 Power Automate "회의비 증빙 수집 필터 (서비스)"
          · 제목·본문·첨부 파일명을 정규화(소문자, 공백·기호 제거)해 팀 키 123개와 비교
          · 하나라도 맞으면 → submit@jnuai-meetingfee.com 으로 '[수집] 원래 제목' + 메타데이터 + 첨부
              └ Cloudflare Email Routing → (지금) Gmail / (다음) Email Worker → FastAPI 웹훅
```

- **OWA** = Outlook Web Access(현재 이름 Outlook on the web). 학교가 직접 운영하는 Exchange 메일 서버의 웹메일 화면이다(`email.jnu.ac.kr/owa`).
- **종희 Power Automate가 끼는 이유**
  1. 담당자 OWA에서는 Power Automate를 쓸 수 없다.
  2. OWA 규칙으로 외부 주소에 보내면 학교 서버가 조용히 막는다.
  3. 학교 내부 주소(종희 Microsoft 365 메일)로는 전달된다. 이 계정의 Power Automate "새 메일 보내기"는 외부로 나갈 수 있다.
  4. 그래서 종희 계정이 **중계 + 정밀 필터** 역할을 한다.
- **Cloudflare를 거치는 이유:** Power Automate에서 서버로 바로 보내는 "HTTP" 동작은 유료(Premium)라 학생 계정에서 쓸 수 없다. 그래서 무료 "메일 보내기"로 내보내고, 그 메일을 받을 곳이 필요하다. 서버가 직접 받으려면 메일 서버(25번 포트)가 필요한데 클라우드 서버는 보통 막혀 있다. Cloudflare가 무료로 받아 Email Worker로 서버 웹훅(HTTP)에 넘긴다. 서버 주소가 바뀌어도 Cloudflare만 고치면 되고 담당자 규칙·흐름은 그대로다. **2026-10-30 확인:** 종희 계정 라이선스는 Power Automate Free + Power Automate for Office 365이고, 프리미엄 커넥터가 꺼져 있다(HTTP 동작에 💎 표시). 그래서 흐름에서 FastAPI로 바로 보낼 수 없다.
- 첨부 조건은 10/30에 뺐다. 첨부 없는 메일도 들어오고, 서비스가 "미첨부" 보완 요청 대상으로 처리한다.
- 담당자 계정에는 받은 편지함 규칙 1개만 추가했다. 다른 설정은 건드리지 않았다. 절차는 `docs/mail/manager-visit-runbook.md` (내부 기록, 공개본에서 제외)에 있다.

## 4. 회신 (잠정, 담당자와 논의 필요)

담당자 이름으로 서비스가 자동 발송할 수 없다. 우선 아래 방식으로 간다. 학교 웹메일이 지원하는지는 아직 시험 전이다.

- **[웹메일에서 열기]**: OWA 새 메일 창 주소(`compose_url`)에 받는 사람·제목·본문을 채워 연다.
- **[초안 복사]**: 본문이 길어 주소에 다 못 넣을 때(한글 약 200자 넘음) 쓴다.
- **[보냈음 표시]**: 담당자가 직접 보낸 뒤 누른다 → `POST /submissions/{id}/reply/mark-sent`
- 제약: 스레드 회신이 아니라 새 메일이다. 실제로 보냈는지 서비스가 알 수 없다.
- `POST /reply/send`(서비스가 `noreply@jnuai-meetingfee.com`으로 직접 발송)는 **보류**다. Resend 도메인 인증과 학교 메일 도착(스팸 아님)은 확인했다.

## 6. AI 검수 원칙

### 검수 조건을 만든 과정
1. **입력:** 사업단 문서 2개. `별첨1_회의비_참고사항.hwp`(지침)와 `별첨1-1_회의비_지출증빙_양식.hwp`(회의록 양식)다.
2. **Upstage Information Extract로 지침 값을 추출한다.**
   - 뽑을 항목 23개를 스키마로 넘긴다: 결제 수단, 결제 마감 시각, 1인당 한도, 식비·다과비 결제 시점, 최소 회의 시간, 허용·불가 지역, 영수증 규정, 서명 규정, 제출 기한, 양식 안내 등.
   - 스키마: `backend/experiments/aicollege_upstage/schema.json`
   - 결과: `guide.ie.json` (예: 결제 마감 20:00, 1인 20,000원, 광주 북구)
3. **코드가 판정 조건 초안 20개를 만든다**(`build_rules.py`).
   - 조건마다 판정 주체(코드 / Solar), 미충족 시 등급(부적합 / 보완필요), 기준값, 지침 원문 근거(`source`)를 붙인다.
4. **담당자 검토를 거쳐 확정한다.** 담당자분께 실제 운영 기준을 듣고 조건을 추가·수정·제외했다.
   - 수정: 제출 기한 "사용 후 1주일" → "7일째 18시 전"
   - 추가: 영수증 사진을 못 읽으면 학생에게 다시 제출 요청(R01 미충족, 2026-10-31 변경 — 처음엔 확인필요)
   - 제외: 1일 1회·수업시간·카드 예약(서류로 판정할 수 없음)
   - 확정본: `backend/rules/aicollege_club.yaml` (R01~R17, `status: confirmed`)
5. **제출마다 판정한다.**
   - 추출: Upstage **Information Extract API**(`information-extract`)로 회의록 값을 JSON으로 받는다. 스캔본은 **Document OCR API**(`ocr`)로 글자 위치를 읽는다. 서명·영수증 사진 유무는 파이썬 문서 리더(olefile·python-docx·pdfplumber)로 칸 안 그림을 직접 확인한다.
   - 판정: 날짜·금액·시각·지역은 파이썬 코드가 계산하고, 주류·장소·내용 구체성·식비/다과비는 **Solar LLM**(`solar-pro4`, Chat API)이 판단한다. 지침이 바뀌면 1~4단계만 다시 하면 된다.

### 원칙

- 계산은 코드가 하고, 의미 판단만 Solar가 한다. 애매하면 **확인필요**로 둔다.
- 조건 R01~R17은 지침에서 뽑고 담당자 확인을 받았다. R18~R20은 제외.
- Information Extract의 `has_signature`·`receipt_attached`는 믿지 않는다. 셀 안 이미지는 직접 확인하고, 스캔본은 OCR + 잉크 비율로 본다.
- 영수증은 회의록 파일 안에 **사진으로 붙어 온다.** 영수증 사진이 흐리거나 잘려 글자를 못 읽으면 추측하지 않고 **R01 미충족(보완필요)**으로 학생에게 "선명한 영수증 사진으로 다시 제출"을 요청한다. 사람도 읽기 어려운 영수증은 검수할 수 없기 때문이다(2026-10-31 결정, 이전에는 확인필요). 이때 영수증 값에 기대는 다른 조건(승인번호·금액·날짜 등)은 미충족을 덧붙이지 않고 "판정 보류"로 담당자 메모에만 둔다.
- 애매한 구분(식비/다과비)은 두 방식으로 모두 계산해 둘 다 위반이면 미충족, 둘 다 통과면 충족, 엇갈릴 때만 확인필요로 둔다. 담당자 화면에 두 계산을 나란히 보여 준다.
- 결과: 가상 케이스 72/72, 스캔 서명 90/90. 실제 제출본(영수증 사진이 붙은 회의록 파일) 시험은 아직이다(지수 담당).

## 7. 기술 스택

| 항목 | 선택 | 이유 |
|---|---|---|
| 서버 | FastAPI | 프론트 API, 메일 웹훅, `/docs` |
| AI | Upstage Information Extract · solar-pro4 · Document OCR | 실험으로 검증됨 |
| 흐름 | LangGraph (가볍게) | 형식 분기·재시도 |
| DB | SQLite + SQLAlchemy | 담당자 2명 규모, 파일 하나로 배포 |
| RAG/ChromaDB | 핵심 경로 제외 | 조건이 17개로 고정이라 검색이 필요 없음 |
| 패키지 | uv (`pyproject.toml` + `uv.lock`, Python 3.12) | 10/30 전환 |
| 배포 | Docker | — |
| 메일 | Cloudflare Email Routing(수신) · Resend(발신) | 자체 도메인 |

가이드 2차와 다른 점(SSE, ChromaDB, GHCR, Streamlit)은 바꾸지 않고 기록만 해 둔다: `docs/reference/bootcamp/upstage-jnu-llmops/project-guide-phase2.md` (내부 기록, 공개본에서 제외)
