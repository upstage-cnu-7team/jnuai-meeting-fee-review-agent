# 인공지능혁신융합대학사업단 메일 첨부 양식 필터 실험

범위는 사업단 동아리·WE-Meet·캡스톤 회의비 지출 증빙이다. 학생 자료를 레포에 복사하지 않는다. 이전 프로젝트 양식은 이 실험에서 제외한다.

## 실제 재전송 후 확인 (아래 사전 실험 상태를 대체)

2026-10-31 사용자 승인으로 기존 15건을 실제 경로로 재전송했다. 기존 중복 5건·신규 10건(첨부 16개)이 도착했다. 이전 10건 누락의 직접 원인은 첨부의 Base64 이중 인코딩이었다. MIME 디코딩 후에도 Base64인 첨부를 확인된 파일 헤더에 한해서 복구하도록 수정·배포했다.

복구된 실제 신규 10건은 코드에서 회의비 양식 4건·비대상 후보 6건으로 나뉘었다. 양식 4건은 실제 Upstage 검수까지 완료했다. 비대상 후보는 재료 구매 신청서·일정/바로가기·운영/멘토링 서류 및 실제 재전송에 들어 있던 다른 사업단 양식이다. 해당 다른 사업단 양식을 이번 사업단의 통과 대상으로 사용하지 않는다.

별도 Solar 분류는 최초에 다른 사업단 양식 1건을 잘못 통과시켰고, 범위를 명시한 재실행에서는 코드와 10/10 일치했다. 최초 응답은 보존했다. 사람의 정답 판단이 남아 있으므로 코드/AI의 합치도를 실제 정확도라고 보지 않는다. 검토 원본은 서버 `data/intake_review/`, 개별 검토 화면은 레포 밖 `/private/tmp/meetingfee-mail-review/index.html`이다. 실제 파일은 레포에 포함하지 않는다.

재전송·복구·교차검증·명단 반영은 운영 배포 완료했다. 전체 테스트 **97개 통과**. 세부 인계는 `docs/handoff/2026-10-31-backend-session.md` 마지막 절에 있다.

## 재전송 전 사전 실험

Azure 운영 컨테이너 안에서 **분리된 임시 DB·파일 경로**를 설정한 별도 프로세스로 `/api/intake/mail` 라우터를 호출했다. 가상 제목·본문·첨부를 포함한 MIME 81건을 서버로 복사하여 기존 운영 코드와 수정 후보에 각각 입력했다. FastAPI TestClient를 사용했으며 외부 SMTP·Power Automate·Cloudflare Worker를 통과시킨 시험은 아니다. 검수 대기열 호출만 막아 운영 작업이나 AI 호출을 만들지 않았다.

| 2026-10-31 서버 실험 | 기존 운영 코드 | 수정 후보 |
|---|---:|---:|
| 회의비 대상 63건 접수 | 63 | 63 |
| 비대상 18건 중 잘못 접수 | 16 | 0 |
| 비대상 정상 제외 | 2 | 18 |
| 대상 잘못 제외 | 0 | 0 |
| 접수한 건의 제목·본문·첨부·메일 원본 저장 | 전부 확인 | 전부 확인 |
| 처리 후 임시 원본 잔류 | 해당 없음 | 0 |

대상 63건 = 공식 동아리 양식에 정상·위반·미기재를 채운 가상 HWP 50건 + 3양식 정상·카페 위반 원본/PDF 12건 + 대상/비대상 첨부 혼합 메일 1건이다. 비대상 18건 = 계획서·신청서·일반 회의록·영수증·작성 안내 등 가상 DOCX 12건 + 사업단 공식 지침 및 캡스톤/WE-Meet 묶음의 비회의비 구역 발췌 6건이다. 발췌본은 리더 검사용이며 원본 전체에 회의비 양식이 포함된 묶음은 접수한다.

동일 내용·양식의 변형이 포함된 작은 통제 자료집이다. 이 81건에서의 정확도 100%는 실제 전체 메일의 정확도 추정치가 아니다. 실제 학생 제출본 2건은 macOS Downloads 접근 제한으로 이번 실행에서 읽지 못했다. 이전에 건너뛴 실제 10건은 서버 원본이 없어 재전송 전에는 양식 여부를 확인할 수 없다. 스캔·판독 실패는 이 81건의 정확도 측정에 포함되지 않으며, AI로 양식을 확인한 결과도 아니다.

## 수정 내용

- 단어 하나(회의·영수증·결제자 등)만으로 받던 규칙을 제거한다.
- 공식 양식 칸 60% 이상 일치와 **독립된 양식 제목 또는 실제 표 칸 구조**를 함께 확인한다. 안내문 안의 양식명 인용이나 칸 이름 나열만으로 받지 않는다.
- 양식에 예시 글이나 위반 내용이 있어도 접수하고 후속 검수에서 지적한다.
- 모든 수신 원본을 먼저 `data/intake_pending/intake_*.eml`에 0600 권한으로 임시 저장한다. 접수 성공 시 정식 `raw/`·첨부·DB 저장 후 임시본을 지운다. 비대상 확정 시 임시본을 지운다. 처리 예외 시 복구를 위해 임시본을 남긴다.
- 판독 실패·스캔·사진은 `unverified`이며 비대상으로 삭제하지 않는다. 접수하여 후속 AI 검수/담당자 확인으로 넘긴다. 형식 미지원 오류만으로 비대상 여부를 확정하지 않는다.
- 이 사전 실험 당시에는 후보를 운영에 배포하지 않았다. 운영 DB는 실험 전후 5건·첨부 0개였고, 이후 실제 재전송 상태는 위 절을 따른다.

## 실행

```bash
cd backend
uv run python experiments/form_screen/run.py --output out/form_screen_local.json
uv run python experiments/form_screen/server_lab.py make out/form-screen-lab.zip
```

`out/formats/`가 있으면 해당 원본/PDF도 포함한다. 공식 양식 변형 50건은 `experiments/real_form/files/`에서 읽는다. 실제 제출본은 `--real-positive <경로...>`로 지정할 수 있으며 내용·파일명은 보고서에 기록하지 않는다.

서버 묶음에는 공식 양식과 가상 데이터만 들어간다. 운영 코드 교체 없이 묶음을 컨테이너 `/tmp/form-screen-lab/`로 풀어 실행한다.

```bash
PYTHONPATH=/app /app/.venv/bin/python /tmp/form-screen-lab/server_lab.py run /tmp/form-screen-lab --variant baseline
PYTHONPATH=/app /app/.venv/bin/python /tmp/form-screen-lab/server_lab.py run /tmp/form-screen-lab --variant candidate
```

각 실행은 새 `/tmp/form-screen-*/` 아래 DB·원본·첨부를 만든다. `server_baseline.json`, `server_candidate.json`에 메일별 기대/접수 결과를 기록한다. 로컬 회수 결과는 `backend/out/form_screen_server_*.json`이다. 현재 전체 테스트: `uv run pytest -q` **92개 통과**.
